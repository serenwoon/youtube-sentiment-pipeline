# youtube-sentiment-pipeline

[![ci](https://github.com/serenwoon/youtube-sentiment-pipeline/actions/workflows/ci.yml/badge.svg)](https://github.com/serenwoon/youtube-sentiment-pipeline/actions/workflows/ci.yml)

자동차 리뷰 영상 댓글을 수집해 감정을 3분류하고, 그 결과를 골든셋으로 평가하는 파이프라인.

> 이 저장소를 읽는 가장 빠른 방법은 `git log --oneline` 이다. 무엇이 틀렸고 어떻게 되돌렸는지가 커밋 메시지에 순서대로 남아 있다.

2023년 캡스톤에서 댓글 수집과 Superset 대시보드를 맡았다. 감정분석은 AWS Comprehend에 맡겼고, 결과가 맞는지는 따로 확인하지 않았다. 대시보드에 언어별 막대가 서긴 했는데 그 높이가 맞는지 알 방법이 없었다. 그 부분을 다시 만들면서 평가 단계를 넣었다.

## 지금 상태

**어떤 방법도 무작위 추측을 넘지 못했다.** 이게 현재 결과다.

| 방법 | macro F1 | 95% 구간 | 무작위 대비 |
| --- | --- | --- | --- |
| 무작위 추측 | 0.329 | 0.265 – 0.395 | — |
| 다수 클래스 | 0.195 | 0.170 – 0.218 | 유의하게 **낮음** |
| 어휘 규칙 | 0.285 | 0.227 – 0.342 | 구분 안 됨 |
| TF-IDF + 로지스틱 회귀 | 0.334 | 0.269 – 0.400 | 구분 안 됨 |
| **한국어 SBERT + 로지스틱 회귀** | **0.376** | 0.307 – 0.443 | 구분 안 됨 (82.8%) |

SBERT가 무작위보다 +0.045 높지만, 그 차이의 95% 구간이 [−0.049, +0.139]로 0을 품는다. 골든셋이 198건이면 macro F1을 ±0.07보다 정밀하게 잴 수 없고, 표에 있는 간격은 대부분 그보다 작다.

그래서 이 저장소가 지금 보여주는 건 좋은 분류기가 아니라 **좋은 분류기를 골랐다고 착각하지 않는 방법**이다. 계산은 [results/](results/)에 있다.

## 실행

평가 하네스는 표준 라이브러리만 쓴다. 설치할 것이 없다.

```bash
python3 src/evaluate.py data/sample_comments.csv data/sample_predictions.csv
```

```
긍정       7     0     1
```

`--bootstrap`을 붙이면 점수와 함께 구간이 나온다. 실데이터 골든셋에서는 이렇게 나온다.

```
부트스트랩 10,000회 (시드 20260809)

              macro F1   95% 구간
관측값           0.376   0.307 – 0.443
무작위 추측      0.329   0.265 – 0.395

무작위보다 높을 확률 82.8%  (단측 p = 0.172)
→ 95% 기준으로는 무작위 추측과 구분되지 않는다.
```

수집과 분류기는 각각 API 키와 패키지가 필요하다. 각 스크립트 docstring에 적어뒀다.

## 이 저장소에서 실제로 배운 것 세 가지

**1. 기준선을 잘못 잡고 있었다.** macro F1의 하한선은 다수 클래스(0.195)가 아니라 무작위 추측(0.329)이다. 다수 클래스를 자로 쓰면 "1.7배 올렸다"는 착시가 생긴다.

**2. 점수 하나만 적으면 실력인지 운인지 구분할 수 없다.** 처음엔 SBERT의 +0.047을 "처음으로 우연이 아닌 숫자"라고 적었다. 구간을 붙여보니 아니었다. 지금은 구간 없는 점수를 안 적는다.

**3. 튜닝은 이미 노이즈를 재고 있었다.** 교차검증 설정을 시드 하나로 고르고 있었는데, 시드 20개로 다시 재니 채택한 설정이 20번 중 4번만 1위였다. 문서에 적혀 있던 CV 점수는 그 설정의 시드 범위 맨 위 값이었다.

셋 다 "측정이 틀렸다"는 같은 종류의 문제고, 분류기를 바꿔서는 안 고쳐진다.

## 구성

```
src/label.py                 라벨링 (터미널)
src/review.py                규칙 1 재검토
src/evaluate.py              평가 하네스 (--bootstrap으로 구간)
src/tune.py                  설정 교차검증 — 시드 여러 개로
src/baselines/               majority / lexicon / embed_classifier
                             sbert_classifier / zero_shot_llm
```

## 라벨

긍정 / 부정 / 복합 3분류.

'복합'은 "승차감은 좋은데 실내가 싸구려 같다" 같은 댓글을 위한 것이다. 차는 평가 항목이 여러 개라(승차감·연비·마감·가격) 한쪽만 좋은 경우가 흔한데, 이걸 긍정이나 부정으로 몰면 라벨에 노이즈가 섞인다.

`NEUTRAL`은 두지 않았다. Comprehend 같은 서비스는 보통 주는데, "1등" 이나 "형 목소리 좋다" 같은 댓글은 감정이 중립인 게 아니라 차에 대한 평가가 없는 것이라 성격이 다르다. 한 라벨로 묶으면 분류기가 애매한 걸 전부 거기 넣어도 점수가 유지된다. 그래서 라벨로 흡수하지 않고 수집 단계에서 걸렀다.

판정 규칙은 [docs/labeling-guide.md](docs/labeling-guide.md)에 있다. LLM 베이스라인의 시스템 프롬프트도 같은 문서를 옮긴 것이다 — 사람과 모델에게 다른 기준을 주면 그 비교는 방법이 아니라 지시문을 재게 된다.

## 골든셋 만들기

```bash
export YOUTUBE_API_KEY=...

# 1. 영상별로 수집
python3 src/collect_youtube.py VIDEO_ID > data/real/raw_VIDEO_ID.csv

# 2. 후보 뽑기 (영상별로 고르게, 시드 고정)
python3 src/sample_for_labeling.py -n 260 data/real/raw_*.csv > data/real/candidates.csv

# 3. 라벨링 — 키 하나씩. 중간에 끊어도 이어서 된다
python3 src/label.py data/real/candidates.csv data/real/golden.csv
```

200건이 목표인데 260건을 뽑는 건 라벨링 중에 규칙 1로 빠지는 게 나오기 때문이다. 제외된 건수는 `excluded.csv`에, 판정이 애매했던 건 `hard_cases.md`에 쌓인다.

라벨링을 마친 뒤 `src/review.py`로 규칙 1에 걸릴 만한 것만 다시 본다. 실제로 이 단계에서 광고 댓글과 브랜드 조롱 13건이 걸러졌다. 이 스크립트는 골든셋을 덮어쓰므로 `.bak` 사본을 먼저 남기고 임시 파일에 쓴 뒤 한 번에 바꾼다.

## 골든셋을 먼저 만드는 이유

분류기를 만든 다음에 평가셋을 뜨면 기준이 모델 쪽으로 휜다. 잘 맞히는 사례를 무의식적으로 고르게 되기 때문이다. 그래서 라벨링 예산의 일부를 평가 전용으로 먼저 떼어둔다.

한 번 학습이나 프롬프트에 섞이면 되돌릴 수 없다는 점도 있다. 그 뒤에 나오는 점수는 자기 답안으로 채점한 값이 된다.

## 데이터

댓글 원문은 커밋하지 않는다. 저작권과 플랫폼 약관 때문이다. 실데이터는 `data/real/`에 두고 이 경로는 gitignore에 있다. 공개하는 건 스키마와 집계, 평가 결과뿐이다.

`data/sample_*.csv`는 형식 확인용 합성 데이터다. 실제 댓글이 아니다.
