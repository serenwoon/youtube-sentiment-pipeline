# 결과 — 같은 골든셋 위에서의 비교

> 분류 방식을 바꿔가며 재되, **자는 하나로 고정한다.** 모든 행은 동일한 골든셋 200건을 `src/evaluate.py`로 평가한 값이다.

| 방법 | macro F1 | weighted F1 | 비용/1K건 | 지연 | 비고 |
|---|---|---|---|---|---|
| 다수 클래스 (baseline) | | | 0 | — | 하한선. 이걸 못 넘으면 의미 없음 |
| LLM zero-shot | | | | | `src/baselines/zero_shot_llm.py` |
| 임베딩 + 경량 분류기 | | | | | `src/baselines/embed_classifier.py` |
| 오픈모델 + LoRA | | | | | 여력이 되면 |

**아직 비어 있다.** 실행한 값만 채운다 — 추정치나 인용치를 넣지 않는다.

## 읽는 법

- **macro F1을 주 지표로 본다.** 클래스 불균형이 크고(긍정이 압도적) '복합'이 가장 어려운 클래스라, weighted F1은 쉬운 클래스의 성적에 가려진다
- **비용과 지연을 같이 적는다.** 정확도만 보면 항상 가장 큰 모델이 이기는데, 실제 선택은 그렇게 하지 않는다
- 다수 클래스 baseline을 **먼저** 채운다. 이게 없으면 어떤 점수도 좋은지 나쁜지 알 수 없다

## 기록 원칙

각 실행마다 남긴다 — 모델명·버전, 프롬프트 또는 하이퍼파라미터, 실행 일자, 골든셋 버전. **재현할 수 없는 숫자는 숫자가 아니다.**
