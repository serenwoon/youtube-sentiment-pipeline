# 결과

분류 방식별 비교. 전부 같은 골든셋 **247건**을 `src/evaluate.py`로 평가한 값이다.

**골든셋**: 자동차 리뷰 영상 5개에서 후보 260건을 뽑아 수작업 라벨링. 제외 13건(5.0%), 최종 247건.
분포는 긍정 101 (40.9%) / 부정 72 (29.1%) / 복합 74 (30.0%).

| 방법 | macro F1 | weighted F1 | 비용/1K건 | 지연 | 비고 |
| --- | --- | --- | --- | --- | --- |
| 다수 클래스 | **0.193** | 0.237 | 0 | — | 전부 '긍정'. 하한선 |
| LLM zero-shot | | | | | `src/baselines/zero_shot_llm.py` |
| 임베딩 + 경량 분류기 | | | | | 학습셋 필요 — 아래 참조 |
| 오픈모델 + LoRA | | | | | 학습셋 필요 |

나머지는 아직 비어 있다. 실제로 돌린 값만 채운다.

## 다수 클래스 (2026-08-09)

```
평가 247건 — 정확도 0.409

클래스        P       R      F1   지지도
긍정     0.409   1.000   0.580   101
부정     0.000   0.000   0.000    72
복합     0.000   0.000   0.000    74

macro F1    0.193
weighted F1 0.237
```

정확도 0.409는 그럴듯해 보이지만 macro F1은 0.193이다. 긍정만 맞히고 나머지 두 클래스는 하나도 못 맞히기 때문이고, 이 격차가 주 지표로 macro F1을 쓰는 이유다.

## 학습이 필요한 방법은 아직 못 돌린다

임베딩 분류기와 LoRA는 학습 데이터가 필요한데, 라벨링한 건 골든셋뿐이다. **골든셋으로 학습시키면 평가가 성립하지 않는다** — 자기 답안으로 채점하는 셈이 된다.

두 가지 길이 있고, 둘 다 정직하다.

- 남은 미라벨 댓글에서 학습셋을 따로 200~300건 라벨링한다
- 학습 없이 되는 방법(zero-shot, 프롬프트 변형)만 비교하고, 학습 기반은 "학습 데이터 미확보"로 남긴다

## 보는 법

주 지표는 macro F1. 이 데이터는 긍정이 많고 '복합'이 제일 어려워서, weighted F1은 쉬운 클래스 성적에 가려진다.

다수 클래스 행부터 채운다. 전부 '긍정'이라고 답하는 분류기의 점수다. 이게 없으면 나머지 숫자가 좋은 건지 나쁜 건지 판단할 기준이 없다.

```bash
python3 src/baselines/majority.py data/real/golden.csv > /tmp/majority.csv
python3 src/evaluate.py data/real/golden.csv /tmp/majority.csv
```

이 값은 골든셋의 클래스 분포에 따라 크게 달라진다. 긍정이 몰려 있으면 높게 나오고, 고르면 낮게 나온다. 그래서 **점수와 함께 분포도 적어둔다.** 나중에 "왜 이때는 0.4였지" 하고 헷갈리지 않으려면 필요하다.

비용과 지연도 같이 적는다. 정확도만 보면 항상 큰 모델이 이기는데 실제로는 그렇게 고르지 않는다.

## 기록할 것

실행할 때마다 모델명과 버전, 프롬프트나 하이퍼파라미터, 날짜, 골든셋 버전을 남긴다. 몇 달 뒤에 이 숫자가 어떻게 나온 건지 답할 수 없으면 그 행은 지우는 게 낫다.
