# 결과

분류 방식별 비교. 전부 같은 골든셋 **247건**을 `src/evaluate.py`로 평가한 값이다.

**골든셋**: 자동차 리뷰 영상 5개에서 후보 260건을 뽑아 수작업 라벨링. 제외 13건(5.0%), 최종 247건.
분포는 긍정 101 (40.9%) / 부정 72 (29.1%) / 복합 74 (30.0%).

| 방법 | macro F1 | weighted F1 | 정확도 | 학습 | 비고 |
| --- | --- | --- | --- | --- | --- |
| 다수 클래스 | 0.193 | 0.237 | 0.409 | 없음 | 전부 '긍정'. 하한선 |
| 어휘 규칙 | 0.275 | 0.306 | 0.393 | 없음 | `lexicon.py` |
| **TF-IDF + 로지스틱 회귀** | **0.345** | **0.366** | 0.393 | 210건 | `embed_classifier.py` |
| LLM zero-shot | | | | 없음 | 미실시 — API 크레딧 필요 |
| 오픈모델 + LoRA | | | | 210건 | 미실시 |

측정일 2026-08-09. 골든셋 247건 고정, 학습셋 210건(겹침 0건).

## 읽을 만한 것 세 가지

### 1. 정확도는 세 방법이 거의 같은데 macro F1은 1.8배 벌어진다

다수 클래스가 정확도 0.409로 **가장 높다.** 아무것도 학습하지 않고 전부 '긍정'이라고 찍은 결과다. 반면 macro F1은 0.193으로 셋 중 꼴찌다.

TF-IDF는 정확도가 0.393으로 오히려 낮은데 macro F1은 0.345다. 긍정을 조금 덜 맞히는 대신 부정과 복합을 잡기 시작했기 때문이다. **정확도만 봤다면 아무것도 안 하는 쪽을 골랐을 것이다.**

### 2. 클래스 가중치 하나가 macro F1을 0.237 → 0.345로 올렸다

처음 설정(`char_wb(1,3)`, `min_df=2`, 가중치 없음)은 247건 중 **234건을 긍정으로 찍었다.**

```
          긍정   부정   복합
긍정      94     6     1
부정      69     3     0
복합      71     0     3
```

학습셋의 긍정 비중이 50%라 분류기가 다수 클래스로 수렴한 것이다. `class_weight="balanced"`를 넣자 예측이 세 클래스로 흩어졌다.

```
          긍정   부정   복합
긍정      66    21    14
부정      42    14    16
복합      43    14    17
```

설정은 **학습셋 내부 5-fold 교차검증**으로 골랐다. 골든셋은 최종 평가 때 한 번만 봤다.

| 설정 | CV macro F1 |
| --- | --- |
| char_wb(1,3) min_df=2 | 0.234 |
| char_wb(2,4) min_df=1 | 0.222 |
| **char_wb(2,4) min_df=1 + class_weight** | **0.295** ← 채택 |
| char_wb(2,5) min_df=1 + class_weight + C=5 | 0.256 |
| word(1,2) min_df=1 + class_weight | 0.269 |

### 3. 댓글의 63.6%에는 감정 어휘가 아예 없다

어휘 규칙이 247건 중 **157건에서 아무 단어도 못 잡았다.** "기대만큼은 아니지만 나쁘지 않았어요" 같은 문장이 그렇다 — 감정은 분명한데 사전에 있을 법한 단어가 없다.

이게 어휘 규칙이 0.275에서 멈추는 이유이자, 통계 모델이나 LLM이 필요한 이유의 구체적인 형태다.

## 한계 — 210건으로는 부족하다

교차검증 결과가 그대로 말해준다. **학습셋 안에서조차 macro F1이 0.3을 못 넘는다.** 하이퍼파라미터를 바꿔도 0.22~0.30 안에서만 움직였으니, 튜닝이 아니라 데이터가 모자란 것이다.

학습셋과 골든셋의 클래스 분포도 어긋나 있다.

| | 학습(210) | 골든셋(247) | 차이 |
| --- | --- | --- | --- |
| 긍정 | 50.0% | 40.9% | +9.1%p |
| 부정 | 24.8% | 29.1% | −4.4%p |
| 복합 | 25.2% | 30.0% | −4.7%p |

같은 영상에서 같은 방식으로 뽑았는데 긍정이 9%p 높다. 표본 변동일 수도, 라벨링 기준이 미세하게 이동한 것일 수도 있다. 혼동 행렬에서 여전히 긍정 열로 쏠리는 걸 보면 후자의 영향도 있어 보인다.

**다음에 손댈 곳은 하이퍼파라미터가 아니라 데이터다.** 학습셋을 늘리거나, 라벨링 기준을 다시 맞추거나.

## 보는 법

주 지표는 macro F1. 이 데이터는 긍정이 많고 '복합'이 제일 어려워서, weighted F1은 쉬운 클래스 성적에 가려진다.

다수 클래스 행부터 채운다. 전부 '긍정'이라고 답하는 분류기의 점수다. 이게 없으면 나머지 숫자가 좋은 건지 나쁜 건지 판단할 기준이 없다.

```bash
python3 src/baselines/majority.py data/real/golden.csv > /tmp/majority.csv
python3 src/evaluate.py data/real/golden.csv /tmp/majority.csv
```

이 값은 골든셋의 클래스 분포에 따라 크게 달라진다. 긍정이 몰려 있으면 높게 나오고, 고르면 낮게 나온다. 그래서 **점수와 함께 분포도 적어둔다.** 나중에 "왜 이때는 0.4였지" 하고 헷갈리지 않으려면 필요하다.

비용과 지연도 같이 적는다. 정확도만 보면 항상 큰 모델이 이기는데 실제로는 그렇게 고르지 않는다.

## 기록할 것

실행할 때마다 모델명과 버전, 프롬프트나 하이퍼파라미터, 날짜, 골든셋 버전을 남긴다. 몇 달 뒤에 이 숫자가 어떻게 나온 건지 답할 수 없으면 그 행은 지우는 게 낫다.
