# 결과 — 같은 골든셋 위에서의 비교

분류 방식은 바꿔가며 재되, **자는 하나로 고정한다.** 아래 모든 행은 동일한 골든셋 200건을 `src/evaluate.py`로 평가한 값이다. 자가 바뀌면 그건 비교가 아니다.

| 방법 | macro F1 | weighted F1 | 비용/1K건 | 지연 | 비고 |
| --- | --- | --- | --- | --- | --- |
| 다수 클래스 | | | 0 | — | 하한선 |
| LLM zero-shot | | | | | `src/baselines/zero_shot_llm.py` |
| 임베딩 + 경량 분류기 | | | | | `src/baselines/embed_classifier.py` |
| 오픈모델 + LoRA | | | | | 여력이 되면 |

**아직 비어 있다.** 실행한 값만 채운다. 추정치나 다른 데서 가져온 수치를 넣는 순간 이 표는 기록이 아니게 된다.

## 읽는 법

주 지표는 **macro F1**이다. 이 데이터는 긍정이 압도적으로 많고 '복합'이 가장 어려운 클래스라, weighted F1은 쉬운 클래스의 성적에 가려진다. 정작 알고 싶은 것은 어려운 클래스에서 얼마나 버티는가인데 weighted는 그걸 보여주지 않는다.

**다수 클래스 행을 가장 먼저 채운다.** 모든 댓글을 무조건 '긍정'이라고 답하는 분류기의 점수다. 이게 없으면 어떤 숫자가 좋은지 나쁜지 판단할 근거가 없다. 실제로 여기서 걸리는 모델이 종종 나온다.

**비용과 지연을 같이 적는다.** 정확도만 놓고 보면 언제나 가장 큰 모델이 이기지만, 실제 선택은 그렇게 하지 않는다. 0.02 차이를 위해 비용이 스무 배로 뛴다면 그건 선택지가 아니다. 세 열을 나란히 봐야 결정이 된다.

## 기록 원칙

각 실행마다 남긴다 — 모델명과 버전, 프롬프트 또는 하이퍼파라미터, 실행 일자, 골든셋 버전.

**재현할 수 없는 숫자는 숫자가 아니다.** 몇 달 뒤에 "이 0.81은 어떻게 나온 거지"라고 묻게 될 것이고, 그때 답할 수 없으면 그 행은 지워야 한다.
